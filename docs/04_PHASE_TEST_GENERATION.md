# Phase 4 — Candidate Test Generation, Validation, and Bounded Repair

**Status: COMPLETE.** Phase 4 can ask the same logical, stateless PatchProof ADK agent for one
structured pytest candidate, reject it deterministically before execution, convert accepted source
into one immutable hashed artifact, and spend at most one additional model call on repair. A strict
repository-owned `.patchproof.yaml` now controls supported execution templates, generated-test
paths, Python version, and timeout. The model never receives or returns commands.

Phase 4 does not yet orchestrate a PR run, execute installation commands, challenge a generated
candidate on BASE/HEAD, interpret assertion relevance, persist candidate lineage, or publish a
GitHub Check. Those integrations begin in Phase 5.

## Problem solved

Phase 3 produces a grounded behavioral claim, but prose is not executable evidence. Asking Gemini
for arbitrary test text and immediately running it would create several distinct risks:

- the target could escape the generated-test directory or overwrite a repository file;
- the response could contain invalid Python or select a nonexistent/multiple pytest node;
- imports could be invented or reach obvious process/network behavior;
- a model could smuggle installation or test commands into its response;
- BASE and HEAD could accidentally receive different generated bytes;
- repair could become an unbounded retry-until-green loop;
- rejected candidates could lose their audit lineage.

Phase 4 creates a trust boundary between semantic test construction and deterministic execution:

> Gemini may propose one bounded source artifact. Deterministic code decides whether that proposal
> is eligible to become the exact immutable artifact later replayed on both revisions.

## Implemented components

### `.patchproof.yaml` execution contract

The repository root now contains:

```yaml
version: 1
python: "3.12"

install:
  - ["uv", "sync", "--frozen", "--all-groups"]

test:
  command: ["python", "-m", "pytest"]

allowed_test_paths:
  - "tests/patchproof_generated/"

timeout_seconds: 120
```

The schema intentionally uses YAML argument arrays rather than shell strings. `ExecutionContract`
and `ExecutionContractLoader` enforce:

- an 8 KiB file limit and UTF-8 safe YAML parsing;
- an exact schema with unknown fields rejected;
- contract version 1 and Python 3.12;
- one or two bounded installation argument arrays;
- predefined command templates only;
- normalized relative POSIX generated-test directories ending in `/`;
- unique allowed paths;
- a 0.05–300 second timeout;
- no shell parsing or environment interpolation.

The supported command templates are deliberately narrow:

```text
install:
  uv sync --frozen
  uv sync --frozen --all-groups

test:
  python -m pytest
  uv run pytest
```

`python` is deterministically replaced with the configured interpreter path. The pytest runner
appends its own fixed JUnit, plugin, output, and single-node arguments. It now requires a validated
contract and rejects any artifact path outside `allowed_test_paths` before writing bytes.

The install arrays are validated and retained but are not executed in this phase. Phase 5 must
perform that orchestration rather than invent another command path.

### Structured candidate proposal

`CandidateTestProposal` is a strict Pydantic/Gemini output containing only:

| Field | Purpose |
| --- | --- |
| `candidate_id` | Bounded lowercase `candidate-*` audit identity. |
| `target_path` | Normalized relative `test_*.py` target. |
| `test_function` | The one expected top-level pytest function. |
| `source` | Bounded candidate Python source, at most 16,000 characters. |
| `rationale` | Concise audit explanation, not hidden chain-of-thought. |

There is no command, dependency, environment, production edit, or free-form tool field. Extra
fields fail strict local validation. As established by the Phase 3 live test, the provider-facing
schema omits Gemini-unsupported `additionalProperties` while local Pydantic parsing still forbids
extras.

### Candidate semantic task

`AdkGeminiCandidateModel` configures:

- the same logical `patchproof_agent` identity used for claim selection;
- explicit `gemini-3.6-flash` and a mechanical Gemini 3.5-or-newer check;
- `CandidateModelRequest` and `CandidateTestProposal` Pydantic schemas;
- no tools and no prior conversation contents;
- temperature 0.1;
- 4,500 maximum output tokens;
- a 60-second provider timeout;
- fresh in-memory ADK session identity per invocation;
- final-response SHA-256 and model/token/duration accounting in the controller;
- normalized provider failures without exposing provider details to callers.

Claim selection and candidate generation use task-specific schemas because their outputs are
different, but they are not separate collaborating agents. There is no handoff conversation,
delegation, voting, or shared memory. Each is an isolated task call under the same agent identity,
model, no-tool policy, and untrusted-data boundary.

The candidate instruction labels the claim, context, prior candidate, and feedback as untrusted
data. It forbids command generation, production edits, repository search, network/process logic,
skip/xfail behavior, and hidden reasoning. Prompt instructions are policy guidance; deterministic
validation and lack of tools are the enforcement boundaries.

### Deterministic candidate validator

`CandidateTestValidator` applies checks in this order:

1. The target path must be under a contract allowlist prefix.
2. The caller-supplied committed-path set must show that the target does not already exist.
3. UTF-8 bytes must remain under the configured source budget.
4. Python's AST parser must accept the source.
5. Exactly one top-level function whose name starts with `test_` must exist.
6. That function must equal the structured `test_function` field.
7. Relative and wildcard imports are rejected.
8. Explicitly blocked process/network/native modules are rejected.
9. Other non-standard import roots must be grounded in deterministic repository paths or imports
   visible in the bounded context.
10. Selected obvious calls such as `exec`, `eval`, `compile`, `__import__`, `os.system`,
    `os.popen`, `pytest.main`, and `shutil.rmtree` are rejected.

The import allow-set contains Python standard-library roots, `pytest`, roots derived from changed
and snippet paths, and roots parsed from retrieved import/source snippets. This does not import or
execute repository code merely to validate a candidate.

Static Python validation is a filter, not a sandbox. It cannot prove semantic relevance,
determinism, absence of side effects, or resistance to every indirect Python technique. Execution
constraints, identical-byte verification, pytest result parsing, and evidence classification remain
separate controls.

### Immutable replay artifact

After validation succeeds, source is encoded to UTF-8 exactly once:

```text
CandidateTestProposal
        |
        v
CandidateTestValidator
        |
        v
TestArtifact(
  relative_path,
  node_id = path::test_function,
  immutable bytes,
  SHA-256
)
```

The existing Phase 1 `TestArtifact` is the handoff type. Phase 5 must pass the same artifact object
to the BASE/HEAD challenge; it must not regenerate source per revision. The Phase 1 executor hashes
the artifact before and after each execution and rejects drift.

### Bounded repair and lineage

`BoundedCandidateTestGenerator` is run-local and stateful. Its hard rules are:

```text
initial calls <= 1
repair calls  <= 1
total calls   <= 2
```

The initial slot is consumed before awaiting the provider. A second initial call, repair before a
completed initial attempt, concurrent invocation, third total call, or second repair is rejected
before another model call. Provider failure also consumes its call slot; reliability retries are
not silently introduced here.

`CandidateFeedback` contains only a bounded category, summary, and at most four short observations.
It can represent deterministic validation issues now and bounded execution feedback later. Raw
unbounded logs are not returned to Gemini.

Each completed response becomes a `CandidateAttempt` with:

- sequence and `INITIAL`/`REPAIR` origin;
- parent candidate ID and parent artifact hash where available;
- `VALIDATED`, `REJECTED`, or `INVALID_MODEL_OUTPUT` status;
- parsed proposal and immutable artifact when valid;
- structured validation issues;
- bounded repair feedback;
- model/version/token/duration usage;
- SHA-256 of the raw response text.

`CandidateGenerationSnapshot` exposes immutable attempt history and the most recent validated
candidate. State is currently in memory; durable persistence is explicitly deferred to Phase 5.

## Control and data flow

```text
BehavioralClaim + bounded PullRequestContext
validated .patchproof.yaml + committed path set
                    |
                    v
       CandidateModelRequest
       commands deliberately omitted
                    |
                    v
 one isolated ADK/Gemini task call
                    |
                    v
       CandidateTestProposal JSON
                    |
                    v
    strict schema + deterministic validator
          /                         \
         v                           v
 immutable TestArtifact       rejected attempt
 path/node/bytes/hash          structured issues
         |                           |
         |                    optional repair feedback
         |                           |
         +-------------+-------------+
                       v
          CandidateGenerationSnapshot
          at most two total attempts
```

Nothing in this flow runs installation commands, repository code, or generated code. The existing
runner is contract-bound, but Phase 5 owns the end-to-end execution decision.

## Failure behavior

| Failure | Deterministic behavior |
| --- | --- |
| Missing, malformed, non-mapping, or oversized contract | `ExecutionContractError`; no execution. |
| Unknown contract key, wrong Python, command string, or unsupported argv | Validation failure. |
| Unsafe or non-allowlisted target path | Candidate rejected without writing a file. |
| Target already exists in supplied committed paths | Candidate rejected; no overwrite. |
| Oversized or invalid Python source | Candidate rejected before artifact creation. |
| Missing declared test or multiple top-level tests | Candidate rejected. |
| Relative, wildcard, blocked, or ungrounded import | Candidate rejected. |
| Selected dynamic/process/destructive call | Candidate rejected. |
| Malformed or extra-field model response | Recorded as `INVALID_MODEL_OUTPUT`. |
| Response/input exceeds character budget | Response rejected or call prevented respectively. |
| Duplicate candidate ID during repair | Rejected with a structured issue. |
| Repair before initial, duplicate initial, concurrent call | State error before Gemini. |
| Third call or second repair | `CandidateBudgetExceeded` before Gemini. |
| ADK/provider/session failure | Normalized invocation error; no fabricated candidate. |
| Runner receives artifact outside contract | `INVALID_ARTIFACT` on each revision. |

## Alternatives and trade-offs

- **Argument arrays instead of strings:** this removes shell grammar entirely. It is less flexible
  for arbitrary repositories, which is intentional in the frozen allowlisted scope.
- **Complete command templates instead of executable-only allowlisting:** permitting `uv` with
  arbitrary arguments would still allow broad behavior. Exact templates are easier to audit.
- **AST validation before pytest:** fast deterministic rejection keeps malformed model output out
  of the executor. Pytest remains the authority on actual collection/execution later.
- **Grounded imports instead of environment introspection:** importing packages during validation
  could execute code and couple semantic validation to one environment. Context-derived roots may
  conservatively reject legitimate omitted dependencies.
- **One top-level test instead of a generated test module suite:** one node matches the one-claim
  evidence boundary and simplifies exact collection checks.
- **Immutable artifact instead of a filename/source pair:** the content hash and bytes make replay
  identity explicit and reuse Phase 1's proven executor invariant.
- **One repair instead of an agent loop:** a hard budget bounds cost and prevents pressure to tune a
  candidate until it happens to produce the desired differential pattern.
- **Run-local state now instead of premature persistence changes:** Phase 5 must persist lineage as
  part of the real orchestration transaction rather than adding an unused Phase 4 table.

## Tests and what they prove

Phase 4 adds three test modules and strengthens the real executor suite:

- `test_execution_contract.py` proves the repository contract loads, resolves the interpreter
  without a shell, accepts only explicit templates, rejects strings/arbitrary commands, validates
  paths/version/timeouts, fails on unknown keys, and bounds malformed/missing/oversized YAML.
- `test_test_generation.py` uses a real Git context fixture and fake model to prove exact immutable
  bytes/hash/node creation, command omission, allowed/non-overwrite paths, syntax and collection
  shape, grounded/blocked imports, selected call rejection, malformed/extra output handling,
  response/input budgets, repair lineage, and the two-call ceiling.
- `test_adk_test_agent.py` instantiates the real ADK `LlmAgent` without credentials and verifies
  identity/model/schema/tool/history/temperature/token/timeout configuration, Gemini-compatible
  response schema, mocked final-event usage normalization, and safe provider failure handling.
- `test_base_head_challenge.py` now constructs `PytestRunner` from a validated contract and proves
  an artifact outside the configured generated-test directory is mechanically invalid on both
  revisions.

## Limitations and remaining work

- Phase 4 does not execute generated candidates or installation arrays as an orchestrated PR run.
- The candidate-specific schema has mocked ADK boundary coverage rather than a separate billable
  live generation call. The same ADK/Gemini credentials, runtime, and strict-schema compatibility
  path were successfully exercised by the Phase 3 live call.
- Existing committed paths must be supplied by the caller; Phase 5 should derive them from the
  immutable Git tree before generation.
- Import grounding is name-based and can miss re-exports, optional dependencies, dynamic imports,
  namespace packages, or valid dependencies omitted by bounded context.
- Static AST checks do not make generated Python safe against a malicious or highly indirect
  program. The honest security claim remains constrained allowlisted execution, not a sandbox.
- Supported command templates are intentionally limited to uv/Python pytest workflows.
- Installation execution, comparable BASE/HEAD environments, minimal child environments, resource
  isolation, and broader output truncation are later-phase responsibilities.
- Candidate/controller lineage is not yet stored in SQLite workflow records.
- Provider failures consume a slot and are not retried; bounded reliability retry policy belongs to
  Phase 6.
- The control plane, retriever, claim task, candidate task, and executor remain unconnected.
