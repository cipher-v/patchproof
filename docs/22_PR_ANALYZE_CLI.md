# PR Analysis CLI

PatchProof verifies a narrow claim about a pull request. It asks Gemini to select one falsifiable
behavioral claim and generate a pytest candidate, then executes the exact same candidate bytes
against immutable BASE and HEAD revisions. A claim can be supported only when BASE produces
`ASSERTION_FAILED`, HEAD produces `PASSED`, and the semantic assessment finds the assertion related
to the selected claim. Semantic assessment cannot upgrade weak mechanical evidence.

## Current scope

The `patchproof analyze` command currently supports only pull requests in PatchProof's committed
historical manifests. This constrained path is for trustworthy demonstrations of the existing
vertical slice; it is not arbitrary-public-PR support. Manifest lookup supplies immutable revision
identifiers and deliberately does not load benchmark oracle source.

One committed demonstration is available under
[`artifacts/demo_runs/jsonschema-1208/`](../artifacts/demo_runs/jsonschema-1208/README.md). Its
candidate is the test generated by Gemini during the recorded run, not a hidden benchmark oracle.

## Local setup

Install Python 3.12, `uv`, and the Google Cloud CLI, then install the locked project environment:

```powershell
uv sync --frozen --all-groups
gcloud auth application-default login
```

Configure Vertex AI for the current PowerShell session. These are configuration values, not
credentials; never place access tokens or private keys in the repository.

```powershell
$env:PATCHPROOF_GEMINI_PROVIDER="VERTEX_AI"
$env:GOOGLE_CLOUD_PROJECT="patchproof-506606"
$env:GOOGLE_CLOUD_LOCATION="global"
$env:PATCHPROOF_GEMINI_MODEL="gemini-3.6-flash"
```

Run the known jsonschema demonstration locally:

```powershell
uv run patchproof analyze --local https://github.com/python-jsonschema/jsonschema/pull/1208
```

The command may use billable Vertex AI calls. It uses the hardened production policy of one initial
candidate and at most two evidence-driven repairs, stopping when evidence becomes mechanically
discriminating.

## Output and artifacts

Normal output distinguishes environment preparation, claim selection or genuine abstention,
candidate validation and execution, semantic assessment, and the final evidence outcome. True
product or infrastructure failures exit nonzero and show a concise error; `--debug` also prints a
traceback.

Each declared run is stored under `.patchproof/runs/<run-id>/`. `metadata.json`, `pr_context.json`,
and `journal.jsonl` record provenance and progress. Evidence files such as `claim.json`, candidate
source and BASE/HEAD logs, `semantic_assessment.json`, and `result.json` exist only if their stages
occurred. An unexpected infrastructure exception produces `failure.json` and a failure report; it
does not manufacture an evidence outcome.

The short sibling paths `.pp/repositories` and `.pp/w` are intentionally used for cached
repositories and temporary worktrees to avoid Windows path-length failures.
